# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Challenge Context

This repo is the **starting point** for a candidate technical challenge (see `CHALLENGE_DESCRIPTION.md`). The current code is **deliberately flawed** — intentionally ugly UI, only 9 possible short codes (`abc` × 2 chars), in-memory `Map` storage, no validation, no click tracking. The candidate's job is to refactor it within ~2 hours into a clean, persistent, well-tested URL shortener. Submission notes go in `CHALLENGE_SUBMISSION.md`.

Treat existing patterns as targets for replacement, not conventions to preserve.

## Repo Layout

pnpm workspace + Turborepo monorepo:

- `applications/web/` — React Router v7 app (SSR enabled via `react-router.config.ts`). Routes in `app/routes/`, app shell in `app/root.tsx`. Tailwind v4 via `@tailwindcss/vite`. The Vite config sets `envDir: "../.."` so all envs load from the repo root `.env`.
- `libs/engine/` — Workspace package `@url-shortener/engine`. Exported via `src/index.ts` directly as source (no build step required for consumers — `main`/`types` point at `src/index.ts`, and the web app marks it `noExternal` for SSR). Holds domain logic: currently `baseUrl` reader and the (broken) `generateShortCode` + in-memory `shortenedUrls` Map.

Routes:
- `/` (`routes/_index.tsx`) — form with `loader` + `action`; action calls `generateShortCode()` and writes to the in-memory map.
- `/s/:code` (`routes/s.$code.tsx`) — loader looks up the code and `redirect`s, or throws a 404 Response.

## Commands

All scripts run through Turbo from the repo root:

```bash
pnpm install                # install workspace deps
pnpm dev                    # turbo dev — starts web at http://localhost:5173
pnpm build                  # turbo build — engine tsc + react-router build
pnpm typecheck              # turbo typecheck (web runs `react-router typegen && tsc`)
pnpm clean                  # turbo run clean + remove .turbo
pnpm clean:deep             # also removes all node_modules
```

Production / Docker (must stay working — required by the challenge):
```bash
docker-compose up --build   # serves at http://localhost:3000
```

To run a single workspace's script: `pnpm --filter web dev` or `pnpm --filter @url-shortener/engine typecheck`.

There is **no test runner configured** — adding tests is part of the challenge; pick the stack (Vitest is the natural fit with Vite).

## Environment

Single root `.env` (copied from `.env.example`). The only variable today is `PUBLIC_URL`, read by `libs/engine/src/base-url.ts` and used by the web app to build absolute short URLs. Use `5173` in dev, `3000` in Docker (docker-compose injects it).

## Architecture Notes for Refactoring

- **React Router v7 typegen**: typed route props come from `./+types/<route>` (auto-generated by `react-router typegen`). After adding/renaming routes, `pnpm typecheck` regenerates these.
- **Engine as source-only package**: changes in `libs/engine/src/*` are picked up by the web app immediately — no rebuild needed. Keep this property when adding a repository layer / Prisma client unless you have a reason to compile.
- **SSR is on**: loaders/actions run on the server, so a real DB client (e.g. Prisma) belongs in the engine and is safe to import from routes. Don't push DB code into client-only modules.
- **Workspace import path**: `@url-shortener/engine` (declared as `workspace:*` in `applications/web/package.json`).
